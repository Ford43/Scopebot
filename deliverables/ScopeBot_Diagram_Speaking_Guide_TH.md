# ScopeBot: คู่มือเล่าผ่าน Diagram

ภาพส่วนใหญ่อ่านซ้ายไปขวา ยกเว้น Sequence อ่านบนลงล่าง และวงจรส่งต่อคนอ่านตามลูกศร ไม่ต้องอ่านทุกชื่อเทคโนโลยี ให้บอกว่าใครส่งอะไร ระบบทำอะไรต่อ และผลกลับไปไหน

## 1. ScopeBot

ชี้ภาพ: ชี้เอกสารด้านซ้าย ผ่าน ScopeBot ตรงกลาง แล้วไปยังสองช่องทางด้านขวา

เวลา 40 วินาที
แนะนำชื่อเล่นผู้พูดและสมาชิก ก้อง ป๊อกกี้ ฟลุ๊ค ฟอร์ด มอส แล้วกล่าวว่า ScopeBot นำเอกสารมาเป็นแหล่งความรู้ ผู้ใช้ถามผ่าน Web หรือ LINE ระบบค้นเนื้อหาที่เกี่ยวข้องก่อนตอบ
วันนี้จะใช้ Diagram พาดูว่าภายในทำงานอย่างไร แล้วสาธิตระบบจริง

อ้างอิง: ScopeBot.pdf.pdf หน้า 1 และ README.md

## 2. ภาพรวมระบบ

ชี้ภาพ: 1 ซ้าย: ช่องทาง  2 กลาง: Backend  3 ขวาบน: ข้อมูล  4 ขวาล่าง: AI

เวลา 60 วินาที
ชี้ 1 ช่องทาง Web หรือ LINE เป็นจุดรับคำถาม
ชี้ 2 FastAPI ตรวจสิทธิ์และควบคุมการทำงาน
ชี้ 3 PostgreSQL เก็บบัญชี บอท และประวัติ

ยังไม่อธิบาย Cloudflare หรือ embeddings ในหน้านี้
ส่งต่อ: เริ่มจากส่วนที่ผู้ใช้งานมองเห็น คือ Frontend

## 5. Backend รับคำขออย่างไร

ชี้ภาพ: ชี้แถว Web และ LINE แยกกัน แล้วมารวมที่ Router ก่อนแยกไปงานข้อมูลหรือ RAG

เวลา 60 วินาที
ชี้เลข 1 Backend รับคำขอจาก Web หรือ webhook ของ LINE
เลข 2 คำขอ Web ตรวจ JWT บัญชีและสิทธิ์ ส่วน LINE ตรวจ signature
เลข 3 Router เรียกงาน เช่น จัดการบอท เอกสาร หรือแชท
เลข 4 อ่านเขียนข้อมูล เรียก RAG แล้วส่งผลกลับ
ไม่ต้องอ่านทุก endpoint ในช่วงนี้ รายชื่ออยู่ภาคผนวก
ส่งต่อ: ระบบเก็บข้อมูลสามชนิดในคนละส่วน

อ้างอิง: api/main.py; api/auth.py; api/routers/*.py

## 6. ข้อมูล 3 ส่วน

ชี้ภาพ: เริ่มที่ ScopeBot กลางภาพ แล้วชี้ซ้าย ขวา ล่าง ตามชนิดข้อมูล

ส่งต่อ: ดูเฉพาะความสัมพันธ์ฐานข้อมูลที่เกี่ยวกับบอทก่อน

อ้างอิง: api/database.py; api/models.py; rag/ingest.py; docker-compose.yml

## 8. เตรียมความรู้ให้บอท

ชี้ภาพ: ชี้เอกสาร 1 ตามลูกศรไปข้อความย่อย 2, BGE-M3 3 และ ChromaDB 4

เวลา 60 วินาที
อ่าน 1 ถึง 4 ผู้ใช้ส่งเอกสาร ระบบอ่านและแบ่งข้อความ BGE-M3 แปลงข้อความย่อยเป็น embeddings แล้ว ChromaDB เก็บไว้แยกตามบอท
ขั้นนี้เป็นการเตรียมดัชนีความรู้ ไม่ใช่ฝึกโมเดลภาษาใหม่ และยังไม่ใช่ขั้นตอบคำถาม
ส่งต่อ: เมื่อผู้ใช้ถาม ระบบใช้ดัชนีนี้อย่างไร

## 9. ค้นก่อนตอบ

ชี้ภาพ: เริ่มคำถามซ้ายบน ค้นกับ ChromaDB ด้านล่าง แล้วส่ง context ไป Ollama และคำตอบ

เวลา 75 วินาที
ชี้ 1 คำถามใหม่และบริบทคำถามล่าสุดช่วยให้เข้าใจคำถามต่อเนื่อง
ชี้ 2 ตัว embedding แปลงคำค้นเพื่อหา chunks ที่ใกล้เคียงใน ChromaDB และกรองตาม distance
ชี้ 3 เอาข้อความที่ค้นได้เป็น context ส่งให้ Ollama พร้อมคำสั่งและประวัติ
ชี้ 4 คืนคำตอบพร้อมชื่อไฟล์และ snippet ให้ Web ส่วน LINE ส่งเป็นข้อความตาม router
ChromaDB เชื่อมที่การค้นหา ไม่ได้เป็นเส้นลัดเข้าโมเดล
ส่งต่อ: ดูคำถามเดียวกันในลำดับเวลาตั้งแต่ส่งจนตอบ

อ้างอิง: rag/rag_pipeline.py; rag/retriever.py; src/app/hooks/useChatSession.ts; api/routers/line_webhook.py

เวลา 60 วินาที

## 12. ระบบเชื่อมต่อกันที่ไหน

ชี้ภาพ: อ่านทางเข้าซ้ายบน ผ่าน Tunnel และ Nginx จากนั้นแยกไฟล์เว็บกับ API แล้วดูบริการด้านล่าง

เวลา 60 วินาที

Nginx ให้ไฟล์ React กับ browser ส่วนเส้นทาง /api/ ส่งไป FastAPI รวม webhook
