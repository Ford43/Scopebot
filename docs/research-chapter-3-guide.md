# หมายเหตุประกอบร่างบทที่ 3 ของ Scopebot

ร่างนี้จัดโครงสร้างตามบทที่ 3 ของเอกสารตัวอย่างอาจารย์ โดยตรวจเนื้อหาช่วงหน้าเอกสาร 41–89 และตรวจภาพตัวอย่างของขอบเขต ยูสเคส กิจกรรม ฐานข้อมูล พจนานุกรมข้อมูล และหน้าจอ การจัดรูปแบบหัวข้อมี 7 ส่วนตรงกับตัวอย่าง ส่วนเนื้อหาเขียนใหม่ตามโครงการ Scopebot และชื่อโครงงาน NT ที่ผู้ใช้ให้ไว้

## ไฟล์ที่ใช้

- research-chapter-3.html: เปิดอ่านในเบราว์เซอร์ หรือเปิดด้วย Word แล้วบันทึกเป็น DOCX สำหรับจัดรูปเล่มต่อ ยังไม่ได้ตรวจการแบ่งหน้าใน Word
- research-chapter-3.md: ต้นฉบับข้อความสำหรับแก้ไข

## สิ่งที่ต้องปรับก่อนนำส่ง

1. รายการ UC01–UC11 เป็นชุดร่างที่จัดให้จากความสามารถของระบบ ผู้จัดทำให้ดู Use Case เดิมเฉพาะสมัครสมาชิก จึงยังไม่ได้ยืนยันว่าอีก 10 รายการตรงกับเล่มเดิม หากมีรายการเดิม ให้จับคู่ชื่อและเลข UC แล้วปรับชื่อในหัวข้อ 3.2–3.4 พร้อมกัน
2. ในหัวข้อ 3.4 มีคำอธิบายลำดับและทางแยกสำหรับวาดครบ 11 รายการ แต่ยังไม่ได้ใส่ภาพ Activity ที่วาดเสร็จ ไม่ควรส่งเครื่องหมายแทรกภาพแทนแผนภาพจริง
3. ใส่ภาพตามช่องที่กำหนด: Use Case 1 ภาพ, Activity 11 ภาพ, ER 1 ภาพ และหน้าจอ 11 ภาพ รวม 24 ภาพ แล้วลบข้อความคำแนะนำในวงเล็บเหลี่ยม
4. สามารถใช้ภาพสมัครสมาชิกที่กำลังแก้ไขเป็นภาพที่ 3.2 โดยตรวจเส้นทางย้อนกลับให้ชัด และใช้ merge node หากรวมทางเลือกก่อนเข้ากิจกรรมตาม UML อย่างเคร่งครัด
5. ฟังก์ชันที่รวมใน Use Case จัดการบอทและจัดการเอกสารอาจแยกเป็นยูสเคสย่อยได้ตามขอบเขตที่อาจารย์ยอมรับ จำนวน 11 เป็นการจัดกลุ่มฉบับร่าง ไม่ใช่ข้อบังคับของ UML
6. ปรับฟอนต์ ระยะขอบ และเลขหน้าให้ตรงรูปเล่มเดิม ชื่อภาพในร่างใช้ “ภาพที่” ส่วนคำอธิบายยูสเคสและพจนานุกรมข้อมูลใช้ “ตารางที่”

## ประเด็นที่ตรวจให้ตรงระบบ

- Support มีหน้าที่จัดการผู้ใช้ ไม่ใช่ผู้ตอบทุกบอทโดยอัตโนมัติ
- หน้าเว็บสนทนาปัจจุบันต้องเข้าสู่ระบบและตรวจความเป็นเจ้าของบอท จึงไม่ระบุว่าเป็นหน้าเว็บสาธารณะสำหรับลูกค้าทั่วไป หากขอบเขตบทที่ 1 ตั้งใจให้เป็นเว็บสาธารณะ ต้องปรับเอกสารและระบบให้ตรงกันก่อนสรุป
- ผู้ใช้ LINE ไม่จำเป็นต้องมีบัญชี users และไม่ได้เชื่อมตัวตนกับบัญชีเว็บอัตโนมัติ
- การไม่อนุมัติบัญชีและการลบบัญชีเป็นคนละการดำเนินการ
- รหัสผ่านจัดเก็บเป็นค่าแฮช ไม่ใช้คำอธิบายว่าถอดรหัสกลับได้
- conversations.session_id ไม่ใช่ Foreign Key ไปยัง live_sessions.id
- roles ไม่ใช่ตารางแยกในระบบนี้ บทบาทจัดเก็บเป็น Enum
- พจนานุกรมข้อมูลอ้างอิง api/models.py และตรวจแนวทางโครงสร้างกับ migrations ไม่ได้เชื่อมต่อฐานข้อมูลจริงเพื่อตรวจรุ่นที่ติดตั้ง
- การมีค่า default ไม่ได้แปลว่าคอลัมน์มี NOT NULL จึงแยก Required ออกจากค่าเริ่มต้น
- การรับเหตุการณ์ LINE และการบันทึกข้อความไม่รับรองว่าการส่งกลับถึงผู้ใช้สำเร็จทุกครั้ง

## แหล่งตรวจสอบในโครงการ

- api/models.py และ migrations/versions/: ตาราง คอลัมน์ และความสัมพันธ์
- api/auth.py, api/routers/auth.py: การสมัคร เข้าสู่ระบบ บทบาท และการอนุมัติ
- api/routers/bots.py และ api/routers/documents.py: การจัดการบอทและเอกสาร
- api/routers/chat.py, api/routers/line_webhook.py และ api/routers/live_chat.py: กระบวนการสนทนาและรับช่วง
- api/routers/dashboard.py: ความหมายของข้อมูลสรุป
- src/app/routes.tsx และ src/app/components/: โครงสร้างหน้าและส่วนติดต่อผู้ใช้
- docs/semantic-search.md, docs/rag-correctness.md, docs/knowledge-updates.md และ docs/chat-stability.md: เงื่อนไขการค้นหาและการทำงาน

งานนี้เป็นการจัดทำเอกสาร ไม่ได้รันทดสอบประสิทธิภาพหรือแก้ไขระบบ และไม่ได้เปลี่ยนไฟล์บทที่ 4–5 เดิม
