# ทดลอง Chroma และ Qdrant แยกต่อบอท

บอทเดิมใช้ Chroma ต่อไป บอทใหม่เลือก Chroma หรือ Qdrant ได้ก่อนอัปโหลดไฟล์
เมื่อสร้างแล้วจะเปลี่ยนฐานค้นหาของบอทนั้นไม่ได้ ให้สร้างบอทอีกตัวเพื่อเปรียบเทียบ
ทั้งสองระบบใช้โมเดล embedding วิธีแบ่งข้อความ และกติกาการตอบจากหลักฐานเดิม

## เริ่มทดลองในเครื่อง (ไม่ต้องมี Docker)

1. ติดตั้ง dependencies จาก `requirements.txt` ใน Python environment ที่ใช้รัน API
   (ติดตั้ง `qdrant-client` ใน `.venv` ของเครื่องนี้แล้ว)
2. หยุด API เก่า แล้วรัน `alembic upgrade head` เพื่อเพิ่ม migration 004/005
   ในฐานข้อมูลของแอป จากนั้นเริ่ม API และหน้าเว็บรุ่นใหม่
3. ปล่อย `QDRANT_URL` ว่างไว้ใน `.env` เพื่อใช้โหมดทดลองในเครื่อง
4. กรอกชื่อบอท A เลือก **Chroma — ค่าเริ่มต้น** และบอท B เลือก
   **Qdrant — ทดลองเปรียบเทียบ** ก่อนอัปโหลดไฟล์แรก
5. อัปโหลดไฟล์เดียวกันให้ทั้งคู่ หากชื่อไฟล์อยู่ใน Library แล้ว ให้เลือก
   เอกสารเดิมจาก Library ไปผูกกับบอทอีกตัว ไม่จำเป็นต้องแทนที่เนื้อหา
6. รอทั้งคู่พร้อม แล้วถามคำถามชุดเดียวกันในหน้าแชต การ์ดบอทแสดงชื่อฐานค้นหา
   LINE ใช้ฐานค้นหาของบอทที่ผูกกับ webhook นั้นตามปกติ

ใช้บอท Chroma เดิมเป็น A ได้เลย หากมีจำนวนบอทถึงโควตาแล้ว ต้องเพิ่มโควตา
หรือใช้บัญชีทดลองที่ยังสร้างบอทได้ โหมด local เหมาะกับทดลองข้อมูลขนาดเล็ก
แนะนำ API หนึ่งโปรเซส การเปิด/ปิด storage ต่อคำค้นและล็อกไฟล์ในโหมดนี้
ไม่ได้ใช้วัดความเร็วหรือความสามารถรองรับโหลดของ Qdrant Server

## เมื่อพร้อมทดลอง Qdrant Server

ติดตั้ง Docker แล้วเริ่มทั้งระบบพร้อมบริการ Qdrant เพิ่มเติม:

```powershell
docker compose -f docker-compose.yml -f docker-compose.qdrant.yml up -d --build
```

ไฟล์เสริมตั้ง `QDRANT_URL=http://qdrant:6333` ให้ API อัตโนมัติและเก็บข้อมูล
ใน named volume `qdrantdata` บริการนี้อยู่ในเครือข่าย Docker ไม่เปิดพอร์ตสู่ host
หาก API รันนอก Docker ให้ใช้ Qdrant Server ที่เข้าถึงได้และตั้ง `QDRANT_URL`
ตามที่อยู่จริง พร้อม `QDRANT_API_KEY` หากเซิร์ฟเวอร์นั้นตั้งการยืนยันตัวตนไว้

บอท local เดิมยังอ่านฐาน local เดิมได้หลังตั้ง URL ส่วนการประมวลผลใหม่จะสร้าง
generation ใน Server แล้วสลับใช้งานเมื่อสำเร็จ ฐาน Server ที่เผยแพร่แล้วต้อง
เข้าถึง Server เดิมได้ต่อไป; การลบ URL ไม่ได้ย้ายข้อมูลกลับ local อัตโนมัติ

## สิ่งที่ควรเทียบ

เริ่มจากคำถามที่ตอบได้ชัดเจนในเอกสาร คำถามภาษาไทยแบบสั้น/ยาว และคำถามที่
ไม่มีคำตอบ ตรวจหลักฐานที่ค้นเจอและความถูกต้องของคำตอบก่อนเทียบเวลา แล้วลอง
เพิ่มไฟล์อีกหนึ่งไฟล์ระหว่างคุย ทั้งสองบอทต้องตอบจากฐานเดิมต่อได้จนฐานใหม่พร้อม

เพื่อให้ใช้เกณฑ์เดิมได้ ตัวเชื่อม Qdrant ใช้ Euclidean distance แล้วแปลงเป็น
ระยะห่างยกกำลังสองให้ตรงกับ Chroma L2 ค่า threshold `1.05` จึงอยู่ในมาตรวัดเดียวกัน
ไม่ได้เปิด hybrid search หรือเปลี่ยนโมเดลเฉพาะฝั่งใดฝั่งหนึ่งในรอบทดลองนี้

ข้อมูลแต่ละรุ่นแยก collection/storage และเผยแพร่ผ่านตัวชี้ในฐานหลักหลังตรวจ
revision สำเร็จ บอทที่ประมวลผลผิดพลาดไม่สลับฐาน และไม่มีการ fallback ข้าม
Chroma/Qdrant แบบเงียบ ๆ ผลทดสอบจึงยังระบุได้ว่ามาจากระบบใด

เอกสารอ้างอิง: [Qdrant Quickstart](https://qdrant.tech/documentation/quickstart/)
และ [Qdrant Python Client](https://github.com/qdrant/qdrant-client)
